# พยากรณ์หลานจ๋ามาวันไหน

เว็บปฏิทินการมาเยือนของหลาน ใช้ Node.js 24 ขึ้นไป ในเครื่องเก็บข้อมูลด้วย SQLite และบน Netlify เก็บข้อมูลด้วย Netlify Blobs

## เปิดในเครื่อง

กำหนด `ADMIN_USERNAME` และ `ADMIN_PASSWORD` ใน `.env` ตาม `.env.example` แล้วรัน `npm start` เปิด `http://127.0.0.1:3000/` หน้าแอดมินอยู่ที่ `/admin` เท่านั้น และต้องเข้าสู่ระบบก่อนบันทึกข้อมูล

ถ้าจะเปิดจากมือถือใน Wi-Fi เดียวกัน ให้ตั้ง `LAAN_LAN_IP` เป็น IPv4 ของคอม เช่น `192.168.1.170` ก่อนรันเซิร์ฟเวอร์ แล้วเปิด `http://<IP>:3000/` บนมือถือ

## ขึ้น Netlify

- ก่อน push ให้รัน `npm run export:netlify` เพื่ออัปเดต `netlify/seed.mjs` จากประวัติจริงใน SQLite แล้วตรวจจำนวนหลานและวันที่มา
- เชื่อม GitHub repository กับ Netlify โดยใช้ค่าจาก `netlify.toml` คำสั่ง build คือ `npm run build:netlify` และ publish directory คือ `dist`
- ตั้ง `ADMIN_USERNAME` และ `ADMIN_PASSWORD` ใน Netlify Environment variables โดยให้ scope ครอบคลุม Functions ห้ามนำ `.env` ขึ้น Git
- หน้าเว็บและรูปอยู่ในไฟล์ static ส่วน `/api/*` เป็น Netlify Functions ข้อมูลเริ่มต้นมาจาก `netlify/seed.mjs` และรายการที่แอดมินบันทึกหลังขึ้นเว็บอยู่ใน Netlify Blobs แบบ site-wide ซึ่งคงอยู่ข้าม deploy
- ตรวจ `/`, `/admin/`, การเข้าระบบ, รูปหลาน, การบันทึก และการพยากรณ์บนลิงก์ HTTPS หลังขึ้นเว็บ

การล็อกอินเก่าจากเครื่องนี้ไม่ย้ายขึ้นเว็บ ผู้ใช้เข้าสู่ระบบใหม่ด้วยบัญชีที่ตั้งไว้ใน Environment variables คุกกี้แอดมินบน HTTPS เป็น `Secure` และ `HttpOnly`

ข้อมูลจริงในเครื่องยังอยู่ที่ `data/calendar.sqlite` สำรองด้วย `npm run backup` ไฟล์นี้และ `.env` ถูกยกเว้นจาก Git รหัสหลานถูกเก็บถาวรในฐานข้อมูล เพื่อไม่ให้ประวัติสลับคนเมื่อเพิ่มรูปใหม่

## การพยากรณ์และทดสอบ

พยากรณ์ 28 วันจากข้อมูลจริงอย่างน้อย 2 วันที่มา โดยดูระยะห่าง รอบสลับ และวันในสัปดาห์ ผลเป็นแนวโน้ม ไม่ใช่เปอร์เซ็นต์ความน่าจะเป็นที่รับประกันได้ วันที่ไม่มีบันทึกอาจหมายถึงไม่ได้มาหรือยังไม่ได้กรอก

หน้า `/admin` หลังเข้าสู่ระบบมีสถิติการทายย้อนหลังใต้ปฏิทิน ใช้ snapshot คำทายที่ระบบเก็บไว้จริงล่วงหน้า 28 วัน และไม่สร้างคำทายปลอมย้อนหลังจากสูตรปัจจุบัน วันก่อนมี snapshot จะแสดงว่าไม่มีข้อมูลคำทำนายย้อนหลัง

ใน SQLite ใช้ตาราง `forecast_history` เก็บ snapshot คำทายรายวัน และ `confirmed_days` แยกวันที่ยืนยันแล้วว่าไม่มีใครมาจากวันที่ยังไม่ได้กรอก บน Netlify เก็บ snapshot ใน key `forecast-history` ของ Blobs และอัปเกรด key `visits` เป็น `{visits, confirmedDays}` ตอนบันทึก

วันเกิดหลานเก็บใน `birthdays.mjs` โดยผูกกับ stable child ID เดิม เก็บเฉพาะเดือนและวัน ไม่เข้าร่วมการพยากรณ์ การมาเยือนจริง หรือสถิติ accuracy

รัน `npm test` เพื่อตรวจสูตรพยากรณ์ รหัสหลาน การเข้าสู่ระบบ และการบันทึกด้วยฐานข้อมูลทดสอบแยกจากข้อมูลจริง
